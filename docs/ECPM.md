# ECPM and wallet feature permissions

The wallet installs Connor's BRC-229 ECPM semantic module through the existing BRC-98/BRC-100 host. Applications keep using `getPublicKey` with `[2, "p ecpm apply <compressed-point> <logical protocol>"]`, a key ID and counterparty; `remove` with the same scope inverts the mask. Ordinary key calls keep their existing behavior. Unsupported schemes, methods and malformed points fail closed. Private keys stay in the wallet.

The module delegates every ordinary authorization check to the wallet permission manager (`authorizationTTL: 0`). The reviewed canonical `[level, "p ecpm <logical protocol>"]` scope covers apply/remove and all points/key IDs in that exact counterparty scope. It is separate from ordinary keys under `<logical protocol>`. A no-prompt probe cannot display or join consent. Protected keys require separate per-request consent and the existing unlock policy.

Individual requests distinguish Allow once, a memory-only wallet session of up to 30 minutes, and optional remembered on-chain access. Complete explicit BRC-116 app groups can cover self and anyone features together, with selected capabilities shown before approval. Spending remains a separate authorization. Remembering or revoking a token may incur transaction and wallet service fees; the UI explains this. Session access ends on lock, wallet/profile/network change, revocation or expiry. Closing an application page does not revoke it.

Action Labels are DPACP scopes. Approval and grant-management consumers identify the exact label, applying versus reading matching history, and originator. Existing `action label <label>` records retain broad apply-and-read access. Opt-in wallet-internal operation scopes separate those rights, and cannot be called as ordinary key protocols. History access can reveal matching activity from other applications. Distinct grant outpoints are retained in inventories and revocation.

The permission manager and ECPM module are source-derived candidate artifacts, locked by file path and integrity. Each Toolbox backport preserves that wallet's original storage/database/archive bundle version; it does not install a new database format. The upstream source proposal and exact artifact hashes are recorded with the PR. No npm publication is implied.

`npm run test:ecpm` exercises the shipped adapter with real cryptography, an independent scalar oracle, inverse operations, binary BRC-100, denial, no-prompt refusal, scope isolation, protected keys and stale-wallet disposal. It also performs 167 point operations plus transcript signing under one grouped session decision and proves immediate revocation. Empty test token inventory and controlled manifest fixtures do not qualify network services, funding or physical devices. Production builds, repository tests and CI remain required.
