# K1-Only Vault Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drop the R1 spend path: vault outputs become plain P2PKH to per-output BIP32 K1 children; the YubiKey becomes a PIV-ECDH unwrap oracle gating both deposit and withdrawal; the entire R1-K1 template + compressed-at-rest machinery is deleted.

**Architecture:** The vault seed (64-byte BIP39 seed from main mnemonic + vault passphrase) is sealed to the YubiKey's PIV P-256 key (slot 0x82) with the `bsvb-vault-seal-v1` scheme resurrected from commit `904d43e` (merged PR #116, later removed by the R1-K1 rework): ephemeral-ECDH → HKDF-SHA256 → AES-256-GCM, ciphertext in expo-secure-store `vault_seal_v1`. A ceremony tap performs one on-card ECDH to unseal, yields an HD node for derivation/signing, and zeroizes on release. Outputs carry `customInstructions v3 {v:3, type:'K1', keyID:'bip32/<n>'}`.

**Tech Stack:** TypeScript/React Native (Expo), @bsv/sdk 2.4.1 (P2PKH, HD, SymmetricKey, Hash), @noble/curves p256, expo-secure-store, jest, Nitro modules (packages/react-native-yubikey), YubiKit iOS 4.4.0 / yubikit-android 3.1.0.

**Spec:** `docs/superpowers/specs/2026-08-21-k1-vault-design.md`

## Global Constraints

- Work on branch `master` directly (user decision). Commit per task.
- NO stored xpub, wrapped or plaintext. At rest: sealed blob (SecureStore `vault_seal_v1`) + `nextKeyIndex` counter (AsyncStorage meta) only.
- Vault meta bumps to **v:4** (v:3 is occupied by the R1 shape; `getMeta` must fail-close on v!==4).
- customInstructions **v:3** `{v:3, type:'K1', keyID}` — fail-closed decode, no v2 legacy path.
- Pin these constants: `K1_LOCK_LEN = 25`, `K1_UNLOCK_LEN = 108`, `VAULT_DEPOSIT_MIN = 10_000`, `VAULT_MAX_INPUTS = 32`, `VAULT_HARD_MAX_INPUTS = 48`.
- `@bsv/templates` dependency STAYS (utils/localpay/verify.ts imports MandalaToken). Only R1K1Wallet usage and `patches/@bsv+templates+1.10.0.patch` go.
- Native `signEcdsa` (Swift/Kotlin/driver/mock) is KEPT even though the vault no longer calls it — it is device-proven and deleting native code cannot be hardware-verified right now. Only TS consumers go.
- Secrets travel as arrays that are `fill(0)`-ed in `finally`; never in logs, VaultError messages, or React state. (HD node internals are un-zeroizable — accepted residual risk per spec.)

describe('vault sealing', () => {
